# Project structure

MAP separates reusable knowledge from project-specific decisions and generated
outputs.

```text
your-project/
├── .map/                         source of truth
│   ├── map.config.json           project and tool configuration
│   ├── architecture/             system model and boundaries
│   ├── decisions/                architecture decision records
│   ├── patterns/                 adopted MAP patterns
│   ├── prompts/                  reusable product prompts
│   ├── agents/                   roles, permissions, and guardrails
│   ├── evals/                    quality gates and datasets
│   ├── tools/                    tool-specific guidance
│   ├── reports/                  generated reports
│   └── cache/                    local cache
├── CLAUDE.md                     generated by map sync
├── AGENTS.md                     generated by map sync
├── GEMINI.md                     generated by map sync
├── .cursor/rules/map.mdc         generated by map sync
└── .github/copilot-instructions.md
```

## What belongs in `.map/`

- Stable knowledge an AI assistant needs to work safely in the project.
- Architecture decisions and the reasons behind them.
- Prompts, evaluation rubrics, and adopted patterns that should be reviewed.
- Tool budgets and policies shared by local development and CI.

Generated reports and caches are ignored by default. Generated assistant files
can be recreated at any time with `map sync`.

## Repository structure

The MAP repository follows the same separation:

- `library/` is reusable knowledge.
- `tooling/` turns that knowledge into commands and packages.
- `apps/` contains user-facing applications powered by the library.
- `docs/` explains how the pieces fit together.
