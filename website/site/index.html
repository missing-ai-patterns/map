What is MAP?

MAP is not another AI framework. It documents the architectural patterns behind AI systems — retrieval, memory, agents, security, evaluation, routing — the way software engineering documents design patterns: name it, compare it, show it working.

Every pattern is written the same way. It states the problem, says when to use the pattern and when not to, lays out trade-offs and failure modes, and ships a small reference implementation plus a copy-pasteable prompt for your coding agent. The goal is to help you make a decision, not to sell you a library.

Libraries come and go. The patterns underneath them last longer.

How you use it

The map CLI reads the same registry this page is built from. Point it at a project:

$ map analyze .
  Detected 3 concept(s):
    LLM Usage (90%)      — requirements.txt: openai
    Vector Search (90%)  — requirements.txt: chromadb
    RAG (60%)            — requirements.txt: langchain

$ map recommend .
  [high]   security/prompt-injection-defense  — triggered by: rag, vector_search
  [medium] evaluation/golden-dataset          — triggered by: llm, rag

$ map add security/prompt-injection-defense
  created .map/patterns/security/prompt-injection-defense/prompt.md
  created .map/patterns/security/prompt-injection-defense/acceptance.md

Then paste the pattern's prompt.md into Claude Code, Cursor, or Gemini CLI — and review the result against acceptance.md. MAP gives your agent architectural context and guardrails; the agent still writes the code.
